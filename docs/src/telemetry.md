# Telemetry in Zed

Zed does not send telemetry or crash reports anywhere.

## Local Event Log

Zed can record usage events (for example which features are used and which languages files are written in) to a log file on your machine. This is off by default. To turn it on, open Settings ({#kb zed::OpenSettings}) and search for "telemetry", or add the following to your settings file:

```json [settings]
"telemetry": {
    "metrics": true
},
```

When enabled, events are appended to `telemetry.log` in Zed's logs directory. The file is emptied each time Zed starts and is never uploaded. Events generated by a remote server are forwarded to the local Zed instance and recorded in the same file.

To view the recorded events, run {#action zed::OpenTelemetryLog} from the command palette or click `Help > View Telemetry`.

When the setting is disabled, no events are recorded.

## Crash Diagnostics

When Zed panics, the panic message and a backtrace are written to Zed's log file.

Zed can also write a [minidump](https://learn.microsoft.com/en-us/windows/win32/debug/minidump-files) and a metadata file to the logs directory when it crashes. This is off by default, and is enabled by starting Zed with the `ZED_GENERATE_MINIDUMPS=1` environment variable. These files stay on your machine and are not deleted automatically. See [Debugging Crashes](./development/debugging-crashes.md).
